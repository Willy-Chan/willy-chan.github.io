# "EP" Libraries Background

- Review standard MoE All to All pattern
- Before DeepEP, we had to rely on CPU-driven AlltoAll kernels

- DeepEP pioneered using NVSHMEM + IBGDA to do DEVICE-INITIATED COMMUNICATION very well
- Literally just a dispatch/combine kernel using NVSHMEM
  - But did a lot of smart things with NVSHMEM, e.g. warp specialization
  - Used IBGDA via NVSHMEM for inter-node comms
  - Handled hot experts in a smarter way





```c
__global__ moe_dispatch_kernel() {
    int my_thread_idx = threadIdx.x;
    int warp_id = my_thread_idx / 32;
    int lane_id = my_thread_idx % 32;

    // all warps can share this shared memory:
    //     [num_toks_going_to_rank_0, num_toks_going_to_rank_1, etc...]
    __shared__ int shared_token_counts[MAX_RANKS];
    if (my_thread_idx < MAX_RANKS) {
        shared_token_counts[my_thread_idx] = 0;    // init to 0 by default
    }
    
    __syncthreads();

    // ------------------------------------------------------------------------
    // PHASE 1: WORKLOAD EXECUTION (Both warps active concurrently)
    // ------------------------------------------------------------------------
    if (warp_id == COORDINATOR_WARP_ID) {
        // coordinator warp's job is to count up the total toks per rank using shared memory atomics. We want to create the map: {r0 processes 2 toks, r1 processes 1 tok, etc.}
        for (int i = lane_id; i < num_tokens; i += 32) {   // each thread handles subset of tokens
            int target_rank = token_to_rank[i];
            atomicAdd(&shared_token_counts[target_rank], 1);  // atomic thread updates to shared memory region
        }

    } else if (warp_id == SENDER_WARP_ID) {
       // sender warp's job is to actually send the data out!

       // notice stride: each thread is sending a small share of the tokens
       for (int i = lane_id; i < num_tokens; i += 32) {   // for (token : my_share_of_tokens)
            int target_rank = token_to_rank[i];
            nvshmem_put_token_nbi(globalTokens[i], target_rank);  // async put onto NIC
        }
        // senders clear outbound network
        nvshmem_quiet();
    }
    

    __syncthreads();   // blockwise barrier; both sender and coordinator warp threads have completely finished. COORDINATOR has finished making the map, SENDER has finished putting tokens on the NIC.

    // now all that's left is for COORDINATOR to NVSHMEM_PUT his token counts onto the peer ranks so peer rank actually knows how many tokens they just got!

   // PEER RANK NEEDS TO KNOW HOW MANY TOKENS JUST GOT PUT INTO ITS MEMORY

    // ------------------------------------------------------------------------
    // PHASE 3: SIGNALING PEERS
    // ------------------------------------------------------------------------
    // Only the Coordinator Warp handles signaling, electing a single thread (lane 0)
    if (warp_id == COORDINATOR_WARP_ID && lane_id == 0) {
        
        // Loop over the remote peer ranks we counted in Phase 1
        for (int peer_rank = 0; peer_rank < MAX_RANKS; peer_rank++) {
            int total_sent = shared_token_counts[peer_rank];
            
            if (total_sent > 0) {
                // Ring the doorbell on the destination GPU
                nvshmem_atomic_add(remote_sync_counters, total_sent, peer_rank);
            }
        }
        
        // Final flush to guarantee the signal transactions clear the PCIe/NIC wires
        nvshmem_quiet();
    }
}
```

Launch 1 block of 2 warps: 64 threads, 32 threads / warp

WARP0: Senders
WARP1: Coordinators

COORDINATOR: start counting tokens per rank

SENDER: thread i sends token i + others to respective rank in non-blocking fashion

SENDER: call nvshmem_quiet(): blocks GPU and NIC until EVERY data packet LEAVES the NIC and is on the wire

BOTH SENDER AND COORDINATOR HIT: __syncthreads()
- Sender has put all data into flight and called quiet()
- Coordinator has finished counting tokens

COORDINATOR: 1 thread does an NVSHMEM atomic add on the number of tokens it sent on the wire, then a quiet() operation.

Break out and process the data

# Why NCCL EP?

There are already a lot of MoE communication libraries out there, e.g. DeepSeek's DeepEP or Hybrid-EP. These all operate outside of NCCL and create complex deployments outside of the NVIDIA ecosystem.

- NCCL EP is just an implementation of these EP libraries, just using the standard NCCL GIN Device API, adding vendor support!

- Literally just a library that handles the dispatch and combine operations.



There is a unified API:

- `ncclEpDispatch` and `ncclEpCombine`
  - Each has:
    - Low Latency mode: 
      - Inference decode
      - Small batch sizes of 1-128 tokns
    - High Throughput mode: 
      - training and inference prefill
      - Large batch sizes of 4096+ tokens
- Replaces NVSHMEM and IBGDA kernels with standard NCCL LSA (intra-node) + GIN (inter-node)



It has better buffer management compared to DeepEP, allowing for up to 14x less memory allocation (TODO: understand).
